Rules observed in those files (not inferred from framework habit):

- `info.version: ''`; server `https://api.emporix.io` with no trailing slash; path keys start with `/` and include the service prefix — `.style-guide/writing-standards/api-references.md`
- Operation `summary` in gerund form ("Retrieving a quote"); scopes only in `security` / `securitySchemes`, never repeated in descriptions — `.github/instructions/openapi.instructions.md`
- Common parameters via `$ref` to `components.parameters`; match the service's existing naming (`trait_*` legacy vs `path_*`/`query_*`/`header_*`) — `.github/copilot-docs-review/local-review-checks.md`
- Every user-visible spec change needs a new `{% update date="RELEASE_DATE" … %}` block at the top of `changelog/README.md` in the same PR; never edit existing entries, never touch `changelog/SUMMARY.md` — `.github/instructions/changelog.instructions.md`
- Changelog section heading level conflicts: `.github/instructions/changelog.instructions.md` and recent entries use `#####`; `.cursor/rules/changelog-conventions.mdc` says `####`. Follow `#####` (what the reviewer checks and what `changelog/README.md` uses).
- Generated files, do not edit: `.gitbook/assets/api-references.zip` (rebuilt by `.github/workflows/release-api-files.yaml`)

## Working agreements

- Branch and PR flow, Jira keys, and evidence publishing follow the `emporix-*` skills; issues go through Emporix AI Buddy MCP, PRs through `gh`.
- Markdown for the current ticket lives in one folder, `.ai/runs/{ticket-branch}/`, named the same as the branch and starting with the Jira key. That includes the issue plan and any other note (questions for a product owner, a Figma comparison, a decision). Do not put those files in the repo root or commit them. See `emporix-setup/references/runs-layout.md`.
- Keep `ai-project-knowledge/` current: when a change alters repository conventions, layout, or publishing, update the matching file in the same PR.
- Never commit `.ai/`; never write secrets into `ai-setup.json` or the knowledge files.
