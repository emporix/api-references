## GitBook structure

- `gitbook.yaml`: root `./`, readme `README.md`, summary `SUMMARY.md` (Git Sync).
- `SUMMARY.md` sections: `## Quickstart`, `## Standard Practices`, `## Integrations`, `## API Guides`. Under API Guides each domain lists its services:

```markdown
* [Cart Service](checkout/cart/README.md)
  * [Cart Tutorial](checkout/cart/cart.md)
  * [API Reference](checkout/cart/api-reference/README.md)
    * ```yaml
      props:
        models: true
      type: builtin:openapi
      dependencies:
        spec:
          ref:
            kind: openapi
            spec: cart-api
      ```
```

- `references-only/SUMMARY.md` is a second table of contents listing only the API references (same `builtin:openapi` block, links with `../`).
- `api-guides-and-references/README.md` holds `content-ref` cards for each domain.

## Publishing

| What | How | Trigger | Source |
|---|---|---|---|
| Markdown pages | GitBook Git Sync | push to `main` | `gitbook.yaml` |
| Specs to GitBook | `npx @gitbook/cli openapi publish --spec <spec-id> <path>` — one hard-coded `publish` line per spec | push to `main` touching `*.yml`/`*.yaml`/`*.json`, or manual | `.github/workflows/gitbook-openapi-publish.yml` |
| Specs ZIP download | builds `.gitbook/assets/api-references.zip` from every `api.*` and commits it to `main` as `tech-cicd` | push to `main` touching `**/api.y*ml` / `api.json` | `.github/workflows/release-api-files.yaml` |

The ZIP and the services list are linked from `quickstart/api-intro.md` and `quickstart/list-of-api-services.md`.

## Adding a new service (all steps)

1. Create `{domain-category}/{service}/README.md`, optional tutorial, `api-reference/README.md` (thin shell), `api-reference/api.yml` from `.style-guide/templates/api.yml`.
2. `SUMMARY.md`: service entry, tutorial, `API Reference` link and a `builtin:openapi` block with a new unique spec ID.
3. `references-only/SUMMARY.md`: same reference entry (observed pattern; not stated in the checklists).
4. `.github/workflows/gitbook-openapi-publish.yml`: add `publish "<spec-id>" "<path to api.yml>"` — without it the spec never reaches GitBook (observed; not stated in the checklists).
5. `quickstart/list-of-api-services.md`: row `| [Name](../domain/service/) | `<zip-name>` |`, sorted by file name. ZIP name = service folder name minus `-service`, plus `-api.<ext>`.
6. Changelog entry with `new-feature` (`modules/changelog.md`).

Sources: `local-review-checks.md` § OpenAPI layout, `api-references.md` § Creating a new service; steps 3–4 from the files themselves.

## Adding an operation to an existing service

Only the service's `api.yml` and a changelog entry change; navigation is generated by GitBook from the spec and its `tags`.
